# BP미디어 Rust 서버 전환

현재 상태: **공개 사이트와 관리자 기능의 주요 데이터 처리 및 응답 생성을 Rust/Wasm으로 옮겨 격리 환경에서 검증했다. 운영 배포와 배포 후 실서비스 검증은 아직 완료되지 않았다.** Cloudflare Pages의 라우팅·보안 경계와 일부 요청 조정은 JavaScript에 남으며, 공용 인증 모듈과 별도 Dreampath 앱은 유지한다.

기준은 `origin/main`의 `835a326a`다. 원래 `bpmedia-material3` 작업 폴더와 그 미커밋 변경을 보존하기 위해 별도 `bpmedia-rust-server` worktree와 `feat/rust-server-migration` 브랜치에서 작업한다.

## 실행 구조와 현재 전환 범위

```text
기존 화면 / 외부 앱
  → 기존 Pages 라우팅 + CSP/CORS/CSRF
  → 기존 인증·메뉴 권한·요청 조정
  → Rust/Wasm 데이터 처리·검증·응답 생성
  → 기존 D1 DB 바인딩
```

아래 목록은 전환 과정의 기능별 기록이다. 후속 항목에서 이전된 기능을 확장했으므로 초기 단계의 “기존 JS 유지” 설명은 그 시점의 상태이며 현재 전체 구조를 나타내지는 않는다.

다음 5개 용어집 핸들러의 DB 처리·분류·정렬·검색·응답을 Rust로 옮겼다.

| 경로 | 메서드 | 유지하는 계약 |
|---|---|---|
| `/api/glossary` | GET | 공개/관리자 캐시, 버킷·검색·그룹 출력 |
| `/api/glossary` | POST | 권한·입력 검증 후 생성, 기존 DB CHECK 저장 매핑 |
| `/api/glossary/:id` | PUT | `expected_updated_at` 충돌 409, 단조 증가 수정 시각 |

| `/api/glossary/bot` | GET | 기존 14개 버킷, JSON/텍스트 출력 |

기존 다섯 개의 통계 쿼리를 같은 조건의 단일 집계로 바꿨다. 한국 시간 날짜 경계·빈 DB·오류 응답을 기존 구현과 비교했다. 운영 성능 향상은 측정하지 않았다.

공개 홈의 전체 응답 오류 처리에서 장애 이슈 저장과 오류 로그 저장을 각각 격리한다. 홈 생성 자체가 실패한 상황에 진단 DB도 실패하면 예외가 전파되던 문제를 합성 환경에서 재현했으며, 수정 후 500 JSON 응답을 반환함을 Node 및 격리 workerd/D1의 이중 장애 주입으로 확인했다. 진단 저장이 실패한 경우 해당 기록은 남지 않을 수 있으며 오류는 실행 로그에 남는다.

공개 홈 히어로는 수동 기사·전환 간격·이미지 설정을 Rust에서 한 번에 조회하고 기사 목록까지 같은 Rust 호출로 조합한다. 구형 설정과 이미지 배치, 공개 여부 및 설정 조회 장애를 기존 응답과 비교했고 격리 workerd/D1에서 Rust 경로 및 히어로 장애 시 다른 홈 섹션 보존을 확인했다. 운영 환경의 성능과 데이터는 확인하지 않았다.

기사 생성·수정의 본문 타입·공백 검증도 기존 텍스트 검증과 함께 Rust에서 처리한다. UTF-16 기준 16,384단위를 넘는 본문과 단독 서로게이트가 있는 본문은 변환 크기와 기존 문자열 보존을 위해 JavaScript 검증을 유지하며, Rust 장애 또는 잘못된 응답에도 기존 검증으로 대체한다. 누락·오류·이모지·긴 본문과 격리 workerd/D1의 생성·수정·장애 대체를 확인했다. 운영 데이터와 성능은 확인하지 않았다.

기사 특집명의 공백 정리와 UTF-16 기준 120단위 제한도 같은 Rust 검증 호출로 처리한다. 비문자 입력과 16,384단위를 넘는 입력, Rust 장애 시에는 기존 JavaScript 정규화로 대체한다. 특수 공백·이모지 절단 경계·단독 서로게이트를 기존 결과와 비교했고 격리 workerd/D1에서 생성·수정 저장값을 확인했다.

기사의 이미지 설명, 위치명과 주소도 같은 Rust 호출에서 문자열 여부·앞뒤 공백과 기존 UTF-16 길이 제한을 처리한다. HTML 문자는 기존처럼 제거하지 않는다. 긴 입력과 Rust 장애는 기존 정규화로 대체한다. 타입·공백·이모지 절단·단독 서로게이트를 기존 결과와 비교하고 격리 workerd/D1에서 수정 저장값을 확인했다.

기사 YouTube 주소의 허용 호스트·영상 ID 검사와 표준 주소 변환도 Rust에서 처리한다. 긴 입력, 단독 서로게이트와 Rust 장애는 기존 검증으로 대체한다. 일반·쇼츠·임베드·단축 주소와 유사 도메인, 잘못된 프로토콜·ID를 기존 결과와 비교하고 격리 workerd/D1의 수정 저장값을 확인했다.

관리자 운영 이력의 운영 이벤트·설정·기사·사이트 이슈 표시 문구와 검색 문자열 생성, 출처별 중복 제거, 시간순 안정 정렬, 표시 건수 제한 및 그룹별 집계도 Rust에서 처리한다. 비표준 이력, 이슈 원본 정규화, 메타데이터·기사 스냅샷 해석, 날짜 해석과 출처별 장애 분리는 기존 JavaScript를 유지하고 Rust 응답이 실패하거나 유효하지 않으면 기존 조합으로 되돌린다. 기존 응답과 유니코드·특수 키·출처 부분 실패를 비교하고 격리 workerd/D1에서 Rust 경로 사용 및 장애 시 대체 응답을 검증했다. 운영 이력의 실제 계정·데이터는 확인하지 않았다.

운영 이력 네 출처는 하나의 Rust 호출에서 병렬 조회하고 각 출처 실패는 독립적으로 표시한다. 통합 호출이 실패하거나 응답 형식이 잘못되면 이전 개별 조회로 대체한다. 출처 일부 누락과 통합 호출 실패를 합성 데이터 및 격리 workerd/D1에서 확인했다. 호출 수 감소가 운영 성능에 미치는 영향은 측정하지 않았다.

`functions/_shared/auth.js`는 수정하지 않는다. 용어집 입력의 JS 문자열 변환·UTF-16 길이·숫자 변환 규칙은 기존 `glossary-buckets.mjs`에서 공유한다. `functions/_shared/rust-server.js`는 Pages가 검증한 요청과 내부 조회 조건을 같은 프로세스의 Wasm으로 전달한다. `/__internal/`은 외부 요청에 404를 반환하도록 차단한다. 새 Worker 서비스나 공개 도메인·바인딩·예약을 생성하지 않는다. 이 Rust 모듈은 단독 Worker로 배포하지 않는다. Rust 내부에는 독립 인증 게이트가 없다.

Rust 소스와 빌드 산출물은 `public/` 밖에 있다. `/server-rust/`와 `/work/`는 미들웨어에서도 차단한다. D1 스키마·기존 레코드·R2·공개 화면·URL은 변경하지 않는다. 테스트 DB는 합성 데이터만 사용한다.

## 개발 환경

검증 환경: macOS arm64, Rust 1.99.1, `worker`/`worker-build` 0.8.7, Wrangler 4.97.0, Node 26.5.0. Rust 의존성은 `Cargo.lock`을 커밋 대상으로 관리한다.

최초 설치는 [공식 Rust 설치 안내](https://rust-lang.org/tools/install/)를 따른다.

```bash
rustup target add wasm32-unknown-unknown
cargo install worker-build --version 0.8.7 --locked
npm run build:rust
wrangler pages dev public
```

`build_rust_server.sh`는 `~/.cargo/bin`을 해당 프로세스 PATH에 추가하고 `worker-build` 버전 및 Cargo lockfile을 확인한다. 생성된 `build/`, `target/`는 Git에 넣지 않는다. Rust 최종 바이너리는 Pages Functions와 함께 번들된다.

`strip = "debuginfo"`를 사용한다. `strip = true`는 wasm-bindgen의 externref 테이블을 제거해 빌드가 실패한다([upstream #1014](https://github.com/cloudflare/workers-rs/issues/1014)).


- Node 계약 검사는 실제 Wasm을 실행하고 `835a326a`의 원래 용어집·기사·홈 핸들러(테스트 전용 fixture)와 응답·저장 결과를 비교한다. Node 로더는 WorkerEntrypoint와 D1 타입만 테스트 환경에 맞춘다.
- 별도 Pages 통합 검사는 설치된 Wrangler의 Miniflare/workerd로 **전체 Functions 번들·실제 D1 바인딩**을 실행한다. 운영 자격증명을 사용하지 않으며 외부 fetch는 차단한다. 익명 401, 보기 전용 403, CSRF 403, CORS, 생성·수정·충돌·삭제, 비공개 기사·내부 필드 차단, 내부 경로 404를 확인한다.
- 격리된 Chrome에서 390px·1440px 홈 → 한국 기사 목록 → 기사 상세 흐름, 검색어 복원·기사 링크·canonical·NewsArticle 구조화 데이터·가로 넘침과 5xx 부재를 검사한다. 합성 기사 101건에서 홈·목록 동시 요청 12건과 홈·목록·기사 API·기사 HTML 혼합 동시 요청 24건도 확인했다. 관련 기사 조회 장애를 주입한 다음 요청에서 정상 회복되는 것도 확인했다. 이는 제한된 로컬 회귀 검사이며 실제 운영 부하 시험은 아니다.
- 작업 시작 시 운영 DB P0 조회 결과 0건, 운영 쓰기 0건이다. 로컬 테스트 성공은 운영 배포·실제 관리자 계정 사용·성능 개선의 증거가 아니다.

## 남은 전환 순서와 완료 기준

기념품 행사 CSV 가져오기의 구문 분석, 한글·영문 헤더 인식, 행의 날짜·보관 상태 해석, 분류 연결과 기존 행사 중복 확인·행별 저장, CSV 내보내기와 템플릿 생성은 Rust에서 처리한다. 행사 생성·수정·CSV 가져오기가 공유하는 문자열 정규화와 날짜·숫자 범위 검증도 Rust에서 처리한다. BOM, 인용부호와 줄바꿈, 주석, 공백, 미완성 따옴표, 중복 별칭 우선순위, 구형 분할 날짜 및 검증 오류를 기존 구현과 합성 데이터로 비교했고 격리 workerd/D1의 가져오기·내보내기와 행별 실패 후 계속 진행을 확인했다. 인증과 요청·응답 경계는 JavaScript에 남는다.

CSV 가져오기는 여러 행의 Rust 날짜 검증을 한 번에 호출한다. 100개 합성 행에 정상·오류 행을 섞어 기존 행별 결과와 저장값을 비교했다. 운영 부하나 최대 파일 크기는 확인하지 않았다.

행사 CSV의 빈 행·필수 헤더 판정과 내보내기용 행사 조회도 Rust에서 처리한다. 잘못된 헤더의 인식 항목 순서와 기존 오류 응답, 기존 내보내기 바이트를 비교했다.

CSV 가져오기에 필요한 기존 행사와 분류 조회도 Rust 준비 단계에서 수행한다. 이름이 같은 기존 행사가 여럿일 때 기존 조회 순서대로 선택하는 동작을 합성 데이터로 비교했다.

행사 일괄 수정의 대상 ID, 분류 존재 여부와 보관 상태 검증을 Rust로 이전했다. 숫자 접미사·누락값·잘못된 분류 및 저장 실패 응답을 기존 구현과 비교하고 격리 workerd/D1의 인증·수정을 검증했다.

행사 목록·단건 및 도감 상세의 한글·영문 행사 기간 표시를 Rust에서 생성한다. 연도·월·일의 정밀도, 같은 기간, 같은 달·다른 달의 축약과 구형 범위 밖 날짜를 기존 표시와 비교하고 격리 workerd/D1에서 행사 조회를 확인했다.

행사 슬러그의 초기 정규화, 생성 시 중복 조회와 기존 다섯 차례의 무작위 접미사 선택을 Rust에서 수행하고 실제 저장된 슬러그를 반환한다. 악센트·한글·특수문자와 UTF-16 기준 길이 제한을 기존 구현과 비교했고 합성 DB 및 격리 workerd/D1에서 충돌과 비충돌 생성을 검증했다. 행사명·설명의 공백 제거와 길이 제한은 Rust에서 처리하며 UTF-16 경계 및 긴 공백 입력을 기존 결과와 비교했다.

1. 홈 응답 조합을 이전한다. 기사 관련 점수화와 기사·홈의 주요 조회, 기사 생성 INSERT는 위 표에 표시된 상태다.
2. 나머지 기사 관리와 자료 관리의 쓰기 API: 기존 권한·감사·revision·R2 정리·복구 동작을 보존한다. 인증 코어 변경이 필요하면 별도 명시 승인을 확인한다.
3. 설정·KMS API: 운영 기준을 바꾸지 않고 기존 기록·충돌 방지·fallback을 이전한다.
4. HTML 생성·SEO·미들웨어: canonical·공유 메타·사이트맵·CSP·외부 앱 CORS 계약을 검증한다.
5. 전체 Functions를 함께 배포하므로 Dreampath 서버는 명시적으로 이번 기능 이전에서 제외하되, 공용 번들과 인증/CSP 회귀를 확인한다.

도감 수정은 D1 일괄 실행으로 본문과 관계·검색 색인을 함께 저장하며, 관련 자료·분류·태그·행사가 준비 중 바뀌면 롤백한다. 구형 무버전 요청도 저장 준비 이후 다른 수정이 감지되면 409로 보존한다. 도감 생성과 삭제도 관계·검색 색인을 D1 일괄 실행으로 처리한다. 합성 데이터와 격리된 workerd/D1에서 검증했으며 운영 환경 검증은 남아 있다.

나머지 서버와 위에서 명시한 인증·정규화·후처리 등은 JavaScript 구현이다. 전체 서버 Rust화, 전체 브라우저 검수, 성능 비교, 복구/배포 실증은 미완료다. 사용자는 2026-10-29 전체 작업 완료 후 운영 배포를 지시했다. 기능별 동등성 검사와 전체 완료를 먼저 마치고 새 버전·changelog·표준 preflight를 준비한다. 프로젝트의 커밋·푸시 승인 경계도 별도로 확인한다. 전체 전환을 마친 것으로 표시하지 않는다.

배포 경로에는 production·Dreampath·스냅샷 롤백의 Rust 선행 빌드를 연결했다. 롤백 workflow는 Rust가 없는 과거 소스도 처리하며, `public/`가 있는 스냅샷에서는 그 디렉터리만 배포한다. workflow 실행 및 실제 롤백은 수행하지 않았다.

예약 발행은 저장 시에도 발행 시각을 재확인하고 실제 발행된 기사만 반환한다. 예약 발행과 기사 순서 변경은 편집 기준 시각을 갱신한다.

기사 생성·수정·상태 변경과 해당 이력은 각각 같은 D1 트랜잭션으로 저장한다. 수정 기준 시각이 있는 기사 편집은 D1 트랜잭션에서 재검사하고, 성공적인 수정·상태 변경 시 밀리초 단위로 증가하는 시각을 저장한다. 기준 시각 없는 구형 요청은 기존처럼 잠금 없이 처리한다.

관리자 도감 화면은 합성 API 응답과 실제 관리자 HTML·스크립트를 사용하는 Chrome 검사(`npm run test:admin:memorabilia`)로 보관된 분류가 있는 일괄 수정 창과 검색 인덱스 반영 실패·성공 안내를 검증한다. 인증 및 운영 데이터는 검사 범위가 아니다.

기사 삭제는 존재하는 조회·좋아요·이력·체류·방문 기록을 정리하고 일정의 기사 연결을 해제한 뒤 기사 본문을 같은 D1 트랜잭션에서 삭제한다. 선택적 테이블이나 해당 컬럼이 없는 기존 데이터베이스는 건너뛴다. 트랜잭션 실패 시 삭제가 되돌려지는 것을 합성 DB와 격리된 workerd/D1에서 확인했다. 홈페이지 설정과 R2 이미지·캐시 정리는 여전히 별도 후처리이며 동일 트랜잭션에 포함되지 않는다.

기사 삭제 후 대표 기사 설정 정리는 Rust 설정 snapshot·revision 저장을 사용한다. 객체 형식의 수동 노출 위치와 추가 필드를 보존하고, 동시 설정 수정 충돌 시 최신 값을 다시 읽어 최대 3회 재시도한다. 정리 실패는 기존처럼 삭제 자체를 되돌리지 않으며 운영 로그에 남는다. 합성 동시 수정과 격리 workerd/D1을 검증했다.

공개 홈 메인 스토리는 설정 조회, 수동 지정 우선, 최근 7일 자동 선정, 이미지 설정 정규화와 기사 카드 생성을 Rust에서 처리한다. 자동 메인 스토리의 동률 무작위 선택과 선정 사유 생성도 Rust에서 처리하며 관리자와 예약 작업은 기존 상태 조회 경로를 유지한다. 합성 비교 검사에서 동률·후보 없음·수동 및 기본 모드를 확인했고 격리 workerd/D1의 자동 선정, 수동 미지정, 없는 기사 및 조회 장애 시 섹션 대체와 자동 갱신 경로도 통과했다.

홈 히어로 기사 ID·수동 노출 순서와 전환 간격의 저장값 해석은 Rust로 이전했다. 단일 값·배열·객체와 손상된 JSON, 수치 접미사 및 전환 간격 상·하한을 기존 구현과 비교했으며 격리 workerd/D1에서도 홈 경로를 확인했다. 홈 API 응답 조합도 Rust에서 수행하며 특수 UTF-16 및 Rust 장애 시 JavaScript 호환 경로를 사용한다.

마케팅 통계의 D1 행을 스키마의 텍스트 필드로 직접 읽고 캠페인·여정을 한 번에 처리해 범용 객체 변환을 줄였다. 기사 1,000·방문 10,000건의 로컬 workerd 교차 측정(준비 3회 후 각 10회) 중앙값/p95는 기존 JS 22.80/24.08ms, 범용 객체 Rust 56.39/59.26ms, 타입 적용 Rust 37.01/39.06ms였다. 세 구현의 합성 응답은 동일했으며 Rust가 여전히 느리다. 실제 운영 부하는 검증하지 않았다.

마케팅 방문 로그의 텍스트 필드에 합성 BLOB가 들어간 경우 기존 JS는 바이트를 쉼표로 연결해 처리했으나 타입 적용 Rust는 500을 반환하는 회귀를 격리 D1에서 재현했다. 호환 역직렬화 후 기존 서버와 전체 응답이 일치했고 격리 workerd에서 성공 응답·방문자 식별자 비노출을 확인했다. 정상 합성 데이터 1만 방문 교차 측정(준비 3회, 각 10회) 중앙값/p95는 기존 JS 21.99/23.71ms, 타입 적용 Rust 36.45/38.22ms, 호환 수정 Rust 37.34/39.34ms였다. 실제 운영 데이터 및 다른 비정상 타입은 검사하지 않았다.

검색 성과 보고서의 출처·기간·날짜·행 수·검색어·클릭/노출·중복 검증과 정렬을 Rust에서 수행한다. 기존 오류 문구와 저장 전 검증을 유지하고 고립 UTF-16 서로게이트는 기존 검증기로 처리한다. 5,001개 합성 Google 행, 네이버 표, 잘못된 날짜·개수·중복·이모지 길이와 기존 응답을 비교했다. 격리 workerd/D1에서 인증·저장·오래된 보고서 및 저장 실패 시 기존 값 보존을 확인했다. 실제 Google 계정과 운영 보고서는 사용하지 않았다.

네이버 검색 성과 표의 머리글·연속 순위·숫자·CTR·행 수 해석을 Rust에서 처리한다. 반복 머리글, 빈 표, 잘못된 숫자·순위·CTR, 이모지 및 고립 UTF-16 서로게이트 호환 경로를 기존 파서와 비교했다. 격리 workerd/D1에서 잘못된 표의 400 응답과 이전 보고서 보존을 확인했다. 실제 네이버 보고서는 사용하지 않았다.

공개·관리자 캘린더 안내문의 기본값과 문자열 정규화를 Rust에서 처리한다. 원본 필드 순서·공백·기본값·구형 숫자/배열 및 특수 UTF-16 값을 기존 구현과 비교했으며, 특수 값과 Rust 장애는 기존 호환 경로를 사용한다. 격리 workerd/D1에서 저장·공개 조회 및 정규화 장애 시 대체 동작을 확인했다. 실제 운영 안내문은 변경하지 않았다.

공개 홈 SSR 하단의 전체 방문자·조회수·오늘 방문자 표시 문자열을 Rust에서 한국어 숫자 형식으로 만든다. 1,000명 이상 구분자와 엄격한 조회 실패 처리를 합성 검사하고, 격리 workerd의 HTML에서 정상 수치와 DB 장애 시 0 표시를 확인했다. 실제 운영 방문 통계는 조회하지 않았다.

공개 홈 API의 사이트 설정·기사 섹션·통계·장애 표시 응답 조합을 Rust에서 처리한다. 고립 UTF-16 코드 단위와 Rust 응답 실패에는 기존 조합을 사용한다. 합성 원본 비교와 격리 workerd/D1에서 기사 발췌 경계·섹션 장애·응답 조합 장애 시 현재 기사 보존을 확인했다. 실제 운영 데이터와 추가 직렬화 비용은 측정하지 않았다.

공개 홈 API의 합성 기사 1,000건·방문 10,000건 로컬 workerd 교차 측정(준비 3회 후 각 20회)에서 기존 JS 중앙값/p95는 11.33/13.05ms, Rust 최종 응답 조합 전 16.22/17.18ms, 조합 후 17.16/18.45ms였다. 세 구현의 합성 응답은 일치했다. 중복 직렬화 제거 실험은 별도 측정에서 16.95ms 대비 16.90ms로 차이가 작고 p95는 17.57ms 대비 17.99ms로 나와 공용 어댑터 변경을 보류했다. 제한된 로컬 측정이며 실제 운영 지연·CPU는 미확인이다.

공개 HTML의 canonical 경로와 게시판 페이지 번호가 포함된 제목을 Rust에서 계산한다. 홈·기사 목록·도감 딥링크·개인정보·검색 경로와 페이지 번호를 기존 결과와 비교했으며, 특수 UTF-16과 Rust 장애는 기존 경로로 대체한다. 격리 workerd HTML에서 추적 파라미터가 canonical에 포함되지 않고 페이지 번호와 제목이 유지되는 것을 확인했다. 정적 자산은 기존처럼 페이지 메타데이터 처리를 거치지 않는다. 실제 운영 검색엔진 수집과 추가 처리 지연은 확인하지 않았다.

공개 HTML의 페이지별 구조화 데이터 유형·주제·키워드·탐색 경로 명칭을 Rust에서 제공한다. 모든 기존 페이지 유형의 메타 태그 및 JSON-LD를 기존 문자열과 비교하며, Rust 장애 시 기존 JS 설명값을 사용한다. 격리 workerd에서 한국 기사 목록의 CollectionPage·주제·키워드를 확인했다. 설명값은 호환 대체 코드와 양쪽에 있으므로 변경 시 비교 검사를 함께 실행해야 한다. 실제 검색엔진 반영은 확인하지 않았다.

공개 홈·게시판·특집·주제·용어집의 공유 및 검색 메타 HTML, 이미지 형식·크기와 JSON-LD 구조를 Rust에서 생성한다. 발행자·운영자 정보는 기존 공용 원본을 전달하며 Rust 장애, 특수 UTF-16 또는 비표준 입력에는 기존 렌더러를 사용한다. 페이지 유형과 이미지 형식별 기존 출력, JSON 유효성 및 장애 대체를 비교하고 격리 workerd에서 대체 HTML을 확인했다. 실제 검색엔진과 소셜 미리보기 수집은 확인하지 않았다.

기존 카드뉴스 편집·임베드 화면의 HTML 셸은 Rust에서 생성한다. 관리자 접근 권한·CSP와 카드 데이터 JSON 직렬화는 기존 Pages 경계에 남으며, Rust 오류와 특수 UTF-16 제목은 기존 렌더러로 대체한다. 제목·스크립트 삽입 방지, 편집·임베드 모드와 기존 HTML 동등성을 합성 검사했고 격리 workerd에서 권한·CSP·오류 대체를 확인했다. HTML 템플릿은 호환 대체 코드와 양쪽에 있으므로 수정 시 비교 검사를 함께 실행해야 한다. 실제 관리자 계정과 브라우저 편집은 이번 변경에서 확인하지 않았다.

공개 특집 페이지의 대표 기사·기사 카드·사이드 목록 HTML은 한 번의 Rust 호출로 생성한다. 이미지 주소·날짜·본문 발췌와 색상 값은 기존 처리 결과를 전달하고, Rust 장애나 특수 UTF-16 값은 기존 렌더러로 대체한다. 이미지 유무·제목·태그·본문 이스케이프와 세 영역의 기존 HTML을 합성 비교했고 격리 workerd에서 공개 범위 및 장애 시 페이지 동등성을 확인했다. 실제 운영 콘텐츠는 확인하지 않았다.

격리 workerd/D1에 합성 기사 2건을 사용해 Chrome headless의 390px·1440px에서 특집·주제 페이지의 카드·목록과 가로 넘침을 확인하고 각 기사 링크를 눌러 상세 페이지 이동을 검증했다. 외부 요청은 차단했다. 실제 운영 데이터·실기기와 시각적 디자인 검토는 수행하지 않았다.

공개 주제 페이지 전체 HTML 틀과 부문 선택·활동 카드도 Rust에서 조립한다. 주제 설명과 버전 값은 기존 공용 원본을 사용하며 Rust 장애와 특수 UTF-16 값은 기존 렌더러로 대체한다. 네 주제의 전체 HTML과 격리 workerd 장애 대체를 비교했고 기존 Chrome 합성 모바일·데스크톱 링크 검사를 다시 통과했다. 템플릿은 대체 코드와 양쪽에 있으므로 변경 시 동등성 검사가 필요하며, 추가 Wasm 호출의 운영 성능은 측정하지 않았다.

공개 특집 페이지의 전체 HTML 틀도 Rust에서 조립한다. 기존 내비게이션·푸터·색상·기사 값과 이스케이프 결과를 전달하고, 템플릿 삽입 값은 재해석하지 않는다. Rust 장애 및 특수 UTF-16은 기존 렌더러로 대체한다. 격리 workerd에서 전체 HTML과 장애 대체를 비교하고 Chrome의 390px·1440px 링크 회귀를 통과했다. 호환 대체 템플릿과 Rust 템플릿을 변경할 때 전체 HTML 비교가 필요하며, 추가 Rust 호출의 운영 성능은 측정하지 않았다.

도감 상세의 관련 공개 항목 조회를 상세 Rust 호출에 통합했다. 관련 ID의 기존 JavaScript `parseInt` 규칙과 저장 순서·중복, 자기 자신 및 비공개 제외는 유지한다. 격리 workerd/D1에서 접미사가 있는 ID·배열 ID·중복·잘못된 JSON 및 구형 별도 조회 경로 장애 주입 시 정상 조회를 확인했다. 실제 운영 데이터와 지연 시간은 측정하지 않았다.

도감 상세의 이미지·국가·태그·행사·관련 항목과 링크 응답도 Rust에서 조합한다. 국가명 표는 기존 공용 원본에서 빌드 시 생성해 Rust에 포함하며, 비표준 국가 코드·특수 UTF-16 등 Rust에서 기존 결과를 보장할 수 없는 데이터는 기존 JavaScript 조합을 사용한다. 공개·관리자 범위와 원본 전체 응답을 합성 비교하고 잘못된 JSON, 큰 숫자와 호환 대체를 확인했다. 격리 workerd/D1 회귀를 통과했으며 운영 데이터는 미확인이다.

도감 상세의 합성 관련 항목 10건을 격리 workerd/D1에서 각 30회 교차 측정했다. 기존 JS 조합의 중앙값/p95는 3.192/4.274ms, 국가명 표를 요청마다 전달하는 Rust 조합은 3.605/4.364ms, 빌드 시 포함한 Rust 조합은 3.162/4.022ms였다. 세 응답은 동일했으며 이 제한된 로컬 표본은 운영 지연을 예측하지 않는다. 국가명 원본을 변경할 때는 `npm run build:rust`로 포함 파일을 재생성하고 원본 일치 검사를 실행해야 한다.

도감 이미지 업로드의 MIME 허용 목록과 길이 검증을 Rust에서 수행한다. 큰 이미지 본문 대신 데이터 URL 헤더와 UTF-16 길이만 전달하며, 인증·권한과 R2 저장은 기존 경계에 남는다. 기존 검증 결과·크기 한계·특수 UTF-16 및 장애 대체를 비교하고 격리 workerd와 합성 R2에서 비인증·SVG·크기 초과·서명 불일치의 저장 차단과 정상 PNG의 바이트·헤더 조회를 확인했다. 실제 운영 R2와 업로드 성능은 확인하지 않았다.

기사·도감·설정 등이 공유하는 이미지 파일 서명 판별도 Rust에서 수행한다. 디코딩된 첫 12바이트만 전달하고 기존 JPEG·PNG·GIF·WebP 판별과 불일치 차단을 유지하며, Rust 오류에는 기존 판별기로 대체한다. 다양한 서명·짧은 데이터·임의 바이트를 기존 판별과 비교했고 격리 workerd/R2에서 네 형식의 합성 서명, MIME 불일치 차단 및 Rust 장애 대체를 확인했다. 이 검사는 파일 전체의 유효성을 검증하지 않으며 실제 운영 R2와 추가 호출 비용은 미확인이다.

공용 이미지 저장의 데이터 URL MIME 허용 검사와 확장자 결정도 Rust에서 처리한다. 이미지 본문은 보내지 않고 헤더만 전달하며, 긴 헤더·특수 UTF-16·Rust 장애에는 기존 검사로 대체한다. 기존 MIME 오류 순서와 파일 서명 확인을 유지하며 격리 workerd 및 합성 R2에서 정상 저장과 장애 대체를 확인했다. 운영 R2와 추가 호출의 성능은 확인하지 않았다.

이미지 정리 시 URL에서 R2 키를 추출하는 처리를 Rust로 이전했다. 삭제 대상 보호를 위해 기존 JavaScript 해석 결과와 Rust 결과를 비교하고 다르면 기존 키를 사용한다. 잘못된 퍼센트 인코딩·한글·상대 URL과 오류 대체를 비교했으며 격리 workerd 및 합성 R2의 메타 이미지 교체에서 대상만 삭제하고 다른 객체가 보존되는 것을 확인했다. 실제 운영 R2는 변경하지 않았다.

공개 도감 슬러그 상세 API의 식별자 공백·UTF-16 길이 처리와 공개 전용 조회, 상태 코드·캐시 응답을 Rust에서 처리한다. 잘못된 주소는 400, 없는 항목과 비공개 항목은 404이며, 문자열 경계에서 서로게이트가 분리되거나 호환 조합이 필요한 데이터 및 Rust 장애는 기존 경로를 사용한다. 합성 DB에서 정상·공백·비공개·길이 경계와 기존 응답을 비교하고 격리 workerd에서 캐시 헤더 및 장애 대체를 확인했다. 실제 운영 데이터는 조회하지 않았다.

도감 숫자 ID 상세 API의 조회 결과와 HTTP 응답도 Rust에서 생성한다. 인증과 도감 보기 권한 확인은 기존 Pages 경계에서 수행하며, 승인된 범위만 Rust에 전달한다. 비공개 자료의 익명·권한 없는 계정 차단, 소유자·보기 권한자의 접근과 `no-store`, Rust 장애 시 대체 및 내부 경로 외부 차단을 격리 workerd/D1에서 확인했다. 실제 관리자 계정·운영 데이터는 사용하지 않았다.

도감 행사 목록·단건 조회의 HTTP 응답도 Rust 조회 결과에서 생성한다. 기존 활성·보관 행사 필터, 실시간 사용 수와 날짜 표시 및 400·404·500 오류 응답을 유지한다. 격리 workerd/D1에서 보관 항목의 목록 필터·단건 조회, 없는 ID 및 조회 장애의 오류 응답과 기존 생성·수정·삭제 회귀를 확인했다. 관리자 쓰기 인증은 기존 경계에 남으며 운영 데이터는 확인하지 않았다.

행사 편집 화면은 창을 열 때의 저장 필드 값을 함께 보내고, 서버는 해당 값이 여전히 일치할 때만 원자적으로 수정한다. 다른 운영자가 먼저 수정하면 409를 반환해 먼저 저장된 값과 편집 중인 입력을 보존한다. 기존 버전 클라이언트가 기준값 없이 요청하는 경우 서버 처리 중의 경쟁만 보호한다. 합성 SQLite·격리 workerd/D1에서 오래된 편집, 요청 처리 중 경쟁, 잘못된 기준값 및 정상 재저장을 확인했다. Chrome의 합성 관리자 화면에서는 충돌 메시지·입력 보존과 최신 목록을 다시 연 뒤 저장을 확인했으며 실제 운영 계정은 사용하지 않았다.

관리자 초안 생성은 삽입·초과 초안 정리·생성 결과 조회를 한 D1 배치에서 처리한다. 별도 결과 조회 호출이 실패해 저장된 초안을 실패로 표시하던 간격을 없애고, 배치 내 조회 실패에는 삽입과 정리를 롤백한다. 합성 SQLite에서 마지막 조회 실패와 롤백을, 격리 workerd/D1에서 별도 조회 장애 주입·운영자별 분리·동시 생성·10개 제한을 확인했다. 응답 전 네트워크 단절이나 실제 운영 D1 동작은 확인하지 않았다.

초안의 제목·부제·분류·태그·작성자·이미지 설명·위치 등 텍스트 필드 길이 제한은 Rust에서 처리한다. 입력은 기존 JavaScript 문자열 변환 뒤 제한 길이 부근의 UTF-16 코드 단위만 전달해 이모지와 고립 서로게이트의 기존 잘림 동작을 보존한다. 이미지 업로드·본문·관련 기사 처리 및 플래그는 기존 경계에 남는다. 각 필드의 제한값·특수 문자열과 격리 workerd의 초안 저장을 확인했다.

초안 생성·수정은 텍스트 정규화와 DB 쓰기를 한 Rust 호출에서 수행한다. 중간 정규화 요청을 없애 별도의 재시도 없이 기존 값을 저장하며, 필드 누락은 DB 쓰기 전에 거부한다. 합성 DB에서 분리 처리와 저장 결과·이모지 경계·수정 결과를 비교하고 격리 workerd에서 분리 정규화 경로 장애 주입 및 소유자 격리를 확인했다. 합성 자동저장 30회 교차 측정(준비 5회)의 중앙값/p95는 분리 호출 4.226/4.833ms, 통합 호출 3.973/4.853ms였다. 제한된 로컬 표본이며 실제 운영 자동저장 성능은 확인하지 않았다.

카드뉴스 기사 선택의 발췌 및 항목 응답 조합도 Rust 조회 안에서 처리한다. Editor.js 문단·목록, HTML 제거·엔터티·400 UTF-16 단위 제한을 기존 결과와 비교했으며 고립 서로게이트 등 호환이 불확실한 본문은 기존 JavaScript로 처리한다. 격리 workerd/D1에서 관리자 권한·공개 범위·발췌를 확인했다. 실제 운영 기사와 대량 기사 조회 성능은 확인하지 않았다.

카드뉴스 기사 선택의 기간·정렬·분류·개수 요청 해석도 Rust 조회에 통합했다. 한국 시간 최근 7일 기본 시각은 기존 JavaScript 시계에서 전달하며, 대소문자·잘못된 날짜·`parseInt` 형식·분류·상한과 전체 응답을 기존 구현과 비교했다. 격리 workerd/D1에서 관리자 권한·기간 초 및 필터를 확인했다. 실제 운영 시계·기사 데이터는 사용하지 않았다.

카드뉴스 기사 발췌는 정규식을 재사용하고 UTF-16 잘림 경계만 확인해 반복 변환 비용을 줄였다. 합성 기사 100건을 격리 workerd/D1에서 각 30회 교차 측정(준비 5회)한 중앙값/p95는 기존 JS 8.968/10.071ms, 최초 Rust 10.519/11.393ms, 정규식 재사용 Rust 9.911/10.835ms, 경계 검사 개선 Rust 9.565/10.337ms였다. 네 응답은 동일했으나 최종 Rust도 해당 표본에서 JS보다 느리며, 실제 운영 성능을 예측하지 않는다. 기존 발췌 동등성·특수 UTF-16 대체와 전체 격리 회귀를 다시 통과했다.

공개 용어집 원문 페이지의 가나다 초성 분류·정렬과 용어 카드 HTML을 Rust 조회 안에서 생성한다. 한국어 정렬과 기존 버킷·순서·빈 값 및 이스케이프를 보존하며 구형 비표준 데이터는 기존 JavaScript 정렬·렌더러를 사용한다. 합성 DB에서 한글·영문·불어·잘못된 순서값의 전체 HTML을 원본과 비교하고 격리 workerd에서 공개 페이지·HEAD·스크립트 이스케이프를 확인했다. 실제 용어집 데이터와 대량 용어의 성능은 확인하지 않았다.

용어집 원문 페이지는 조회·카드·전체 HTML을 한 번의 Rust 호출로 조합한다. 구형 비표준 데이터와 조회 실패에는 기존 JavaScript 페이지 생성 경로를 유지한다. 메타·링크의 토큰과 원본 전체 HTML을 합성 데이터로 비교하며 실제 검색 노출과 운영 성능은 아직 검증하지 않았다.

공개 기사 목록의 페이지 번호 링크는 Rust 카드 렌더링에서 현재 URL로 직접 생성한다. 반복된 `page`, 한글 검색어, 공백·특수문자와 잘못된 퍼센트 인코딩의 결과를 기존 JavaScript와 비교했다. 격리 workerd/D1의 18개 합성 기사에서 여러 페이지 및 Rust 렌더러 장애 대체의 링크가 일치했다. 실제 운영 주소와 성능은 확인하지 않았다.

홈 API의 최신 기사와 네 분야 목록을 하나의 Rust 호출에서 병렬 조회한다. 각 조회의 실패는 해당 분야만 빈 목록과 기존 장애 기록으로 처리하고, 묶음 호출 자체의 실패는 기존 개별 조회로 대체한다. 합성 DB에서 원본 전체 응답·한 분야 DB 오류·UTF-16 발췌 경계를 비교했으며 격리 workerd/D1에서 묶음 호출 장애 시 개별 조회 결과를 확인했다. 운영 지연과 DB 부하는 측정하지 않았다.

홈 묶음 응답의 필수 다섯 필드가 배열 또는 개별 오류를 뜻하는 null이 아니면 기존 개별 조회로 재시도한다. 격리 workerd에서 잘못된 형식의 성공 응답을 주입해 홈 목록 복구를 확인했다. 합성 기사 1,000건·방문 10,000건을 사용한 로컬 교차 측정(준비 3회 후 각 20회)에서 개별 조회의 중앙값/p95는 17.78/19.36ms, 묶음 조회는 17.63/19.86ms였으며 매 응답이 동일했다. 제한된 로컬 표본이므로 운영 성능이나 개선을 입증하지 않는다.

방문 기록의 유입 URL 정규화·동일 호스트 판별·UTM 추출을 Rust 조회와 저장에 통합했다. 브라우저와 동일한 URL API를 사용하며 봇 판별, 방문자 식별 및 위치값 준비는 기존 경계에 남는다. 비정상 서로게이트 입력은 기존 JavaScript URL 처리로 대체한다. 합성 데이터에서 잘못된 주소, 중복 UTM과 국제 문자 등을 기존 동작과 비교하고, 격리 workerd/D1에서 80 UTF-16 단위 절단에 따른 고립 서로게이트의 저장 결과를 동일 런타임의 기존 JavaScript 바인딩과 비교했다. 실제 방문 데이터는 사용하지 않았다.

방문 경로에 단독 서로게이트가 포함된 경우에도 UTF-16 코드 단위를 보존해 Rust에서 기존 길이 제한·정리·제외 규칙을 적용하고 D1에 저장한다. 일반 객체 입력을 문자열 경로로 오인하지 않도록 별도 내부 필드를 사용한다. 합성 비교와 격리 workerd/D1에서 동일 런타임의 기존 JavaScript 바인딩과 저장값을 비교했다. 운영 방문 데이터는 확인하지 않았다.

방문 기록의 국가·도시·지역·대륙과 좌표 정규화 및 국가명 조회도 Rust 저장 경로에서 처리한다. 국가명은 기존 공용 카탈로그에서 빌드 시 생성한 자료를 사용하고, 비표준 자료형이나 고립 서로게이트 원본은 기존 JavaScript 처리로 대체한다. 합성 값으로 알려진·미등록 국가, 좌표 범위·반올림, 빈 값과 특수 UTF-16을 원본과 비교했으며, 격리 workerd/D1에서 정상 필드 및 길이 제한 경계의 도시명을 기존 JavaScript 바인딩과 비교했다. 운영 위치 데이터와 실제 성능은 확인하지 않았다.
