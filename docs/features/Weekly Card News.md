# 함께 읽는 스카우트 소식

2026-10-23 구현. 2026-10-24 사용자 요청으로 자동 제작을 중지했다. 관리자에서 필요할 때 수동으로 제작한다.

## 관리자에서 사용하는 방법

카드뉴스 메뉴에서 준비된 주간 호를 열거나 **최근 한 주 카드 만들기**를 누른다. 기사 고르기에서 이번 호의 이미지와 본문을 확인한 후보 중 1~5건을 선택한다. 사진을 더블클릭하거나 키보드 Enter로 위치·확대율과 사진 영역 너비·높이(50~100%)를 조정한다. **변경 내용 저장**으로 서버에 보관하고 현재 카드 PNG 또는 전체 PNG ZIP을 받는다. PNG는 1080×1350이다.

원문 제목·부제·본문 발췌는 기사에서 가져온다. 안내와 CTA는 겸손하고 다정한 Scout 어조로 유지한다. 기사 원본은 수정하지 않는다. 원문 발췌는 공간에 맞게 문장 단위로 줄이고 기사 링크를 안내한다.

## 제작·선정 기준

- 자동 제작 예약은 없다. 별도 Worker `bpmedia-card-news-weekly`의 cron은 빈 배열이며 지연된 scheduled 이벤트도 데이터를 만들지 않는다.
- 관리자의 수동 제작은 실행 시각 직전7일의 공개 기사를 기준으로 한다.
- 기존 KST 공개일 표준 `PUBLIC_DATE_EXPR` 사용. 해당 기간 기사 조회 수 + 공감 수×3, 최신순, ID순으로 후보를 정렬한다. 외부 SNS 관심도는 수집하지 않는다.
- 본문에서 완결된 발췌 문장을 얻을 수 없거나, 이미지가 없거나, 기본 로고이거나, 이미지 응답을 확인하지 못하면 제외한다. 상위 20건의 이미지 응답을 확인한다. 외부 origin으로 리다이렉트하는 이미지는 안전하게 제외한다.
- 한국·아태·세계에서 각 1건을 우선 고르고 나머지를 순위로 채워 최대 5건. 해당 분류가 없어도 제작한다. 나머지 기사는 분류별 최대 4건을 한 줄 말줄임으로 표시한다. 없는 분류는 숨긴다.
- 같은 기간 slug가 이미 있으면 기존 호를 반환한다. 재실행으로 수동 편집을 덮어쓰지 않는다. 후보가 없으면 빈 호를 만들지 않는다.

## 저장·권한·복구

기존 D1 `card_news.data`에 `bpmedia-weekly-v1` 후보·선택·사진 위치·revision을 저장한다. 마이그레이션이나 새로운 테이블이 없다. `published=0`, `auto_publish=false`이며 SNS 자동 게시 기능은 없다. 서버에서는 편집 가능한 호를 만들고 PNG는 브라우저에서 필요할 때 생성한다. 기존 React 카드뉴스는 기존 편집기로 열린다.

보기/쓰기 권한은 기존 `card-news` 메뉴 게이트를 재사용한다. 선택 ID와 사진 좌표를 서버에서 검증하며 revision과 이전 JSON 비교로 저장 충돌을 409로 반환한다. 저장 실패 시 브라우저의 변경을 유지한다. `settings_history`에는 이전 값 기록을 시도한다. API와 편집 화면은 관리자 인증이 필요하며 정적 템플릿에는 기사 데이터를 포함하지 않는다.

과거 `settings.card_news_weekly_status` 기록은 보존하지만 수동 전용 상태 안내에서는 조회하지 않는다. 자동 제작·자동 게시는 꺼져 있으며, 제작 실패 시 관리자의 최근 한 주 카드 만들기로 다시 시도할 수 있다. 기존 카드뉴스와 편집·PNG 다운로드 기능은 유지한다.
