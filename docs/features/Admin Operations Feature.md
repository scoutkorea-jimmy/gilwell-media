# Admin Operations Feature

## 관리자 재정리 계획 · 2026-10-15

승인 근거는 사용자의 관리자 전용 범위 지정과 "작성한 계획에 의거하여 개발을 완성할것" 요청이다. 이 문서에 변경 범위와 기능 대응표를 기록하고 관리자 UI 구현과 `03.156.00` 배포를 완료했다. 공개 Site·Dreampath UI, 실제 콘텐츠와 설정값, 계정·권한 데이터, 기존 미커밋 작업은 보존한다. 커밋・푸시・배포는 [관리자 배포 프로토콜](../../rules/03-deploy.md)에 따라 진행했다. Site `VERSION`은 `00.194.00`을 유지하며 필수 공통 캐시 메타데이터 동기화와 공개 기능/데이터 변경을 구별한다.

이 문서는 관리자 기능의 조사·구성·검증 기록이다. 운영 기준은 관리자 KMS가 정식 원본이며 `docs/feature-definition.md`는 보조 스냅샷이다. 코드에서 관찰한 동작만으로 운영 기준을 새로 정하지 않는다. KMS 원본 대조·동기화 결과와 실환경 검수 결과는 각각 확인된 뒤 기록한다.

### 목표와 순서

1. 변경 전 사이드바 39개 항목과 모든 설정 섹션·모달·업무 연결을 목록화한다. 기능 존재와 사용 빈도를 구분하고, 이용 근거가 없는 기능의 사용 여부는 `미확인`으로 남긴다.
2. 대시보드·기사 운영·자료 관리·노출 관리·성과 분석·운영·설정의 여섯 영역으로 탐색을 정리한다. 좌측 사이드바를 기준 탐색으로 유지하고 관련 업무는 네이티브 `details`/`summary` 하위 그룹으로 접는다. 최종 구현은 같은 `name="admin-tools"`로 한 그룹씩 펼치며, 본문에 같은 메뉴를 반복하지 않는다. 최신 배타적 펼침 회귀 검증은 아래에서 별도 기록한다.
3. 기존 패널·설정 API·권한 슬러그를 재사용한다. 메뉴 위치와 이름을 바꿔도 보기/쓰기 권한, 오너 전용 기능, 민감 메뉴 OTP, 설정·게시글 감사 이력은 보존한다.
4. 홈 노출에 반영되지 않는 구형 에디터 추천 수동 선택·해제·정렬 UI와 중복 계정 보안 UI를 정리한다. 에디터 추천은 자동 선정 기준을 안내하고, 기존 `account-security` 진입은 `account-me`로 연결한다. 저장 데이터와 서버 API는 삭제하지 않는다.
5. 합성 데이터로 전 기능 도달성·권한별 탐색·대표 업무·좁은 화면·키보드 조작을 검증한다. 인증된 프로덕션 검수와 배포 결과는 로컬 검증과 별도 기록한다.

### 완료 기준

- 기존 39개 사이드바 항목 모두에 새 위치 또는 호환 경로가 있다. 숨긴 설정에만 있던 `nav-labels`·`account-security`도 누락 없이 판정한다.
- 관련 기능을 접어도 현재 화면의 메뉴는 표시되고, 권한 없는 메뉴와 항목이 없는 그룹은 표시되지 않는다. 키보드로 그룹을 열고 닫으며 메뉴에 접근할 수 있다.
- 메뉴 통합이 다른 기능의 권한을 부여하지 않는다. `view:<slug>`와 `write:<slug>`, 오너 전용 기능, 직접 패널 접근 검사와 서버 검사는 서로 구별한다.
- 구형 추천 UI에서 `featured`와 `picks_order`를 변경하는 행위가 더는 실행되지 않는다. 자동 추천의 공개 선정 로직은 변경하지 않는다.
- 새 글·임시저장 복원·기사 수정·계정 보안·이슈 상태 변경·자료 편집의 기존 흐름이 보존된다. 실제 운영 데이터로 저장·삭제·권한 변경을 시험하지 않는다.
- 코드 검사, 합성 브라우저 검증, 인증된 실환경 검수, KMS 동기화, 릴리스 상태를 각각 기록한다. 통과하지 않은 단계는 완료로 표시하지 않는다.

### 숨긴 설정·기존 경로의 추가 판정

변경 전 `v3-settings-nav`는 CSS로 숨겨져 있었다. 마크업의 잔존을 화면에 중복 메뉴가 표시된 증거로 간주하지 않는다. 구현에서는 숨긴 보조 메뉴 마크업도 제거하고 좌측 사이드바만 유지한다. 재편 후 공개 메뉴명 진입점 복원으로 사이드바는 40개 항목이며 기존 권한 슬러그는 35개로 유지한다. 위 39개 항목은 기존 `settings` 섹션 18개 중 16개를 포함하며, 나머지 두 섹션은 아래에서 별도로 판정한다. 로그인·세션 타이머·게시글 수정/미리보기·각 자료의 편집 모달은 상위 업무에 속한 보조 흐름으로 유지한다.

| 기존 설정 | 판정 | 권한·호환 조건 |
| --- | --- | --- |
| `settings/account-security` | 중복 비밀번호・OTP UI를 `account-me`로 통합 | 기존 진입은 내 계정으로 연결한다. `/api/admin/password`・OTP API・다른 기기 세션 종료・백업코드는 보존한다. |
| `settings/nav-labels` | 실제 메뉴명 편집을 운영·설정에서 도달 가능하게 한다 | 운영·설정의 사이트 기본설정에 오너 전용 `공개 메뉴명` 진입점을 추가한다. 독립 `nav-labels` 권한은 신설하지 않고 PUT의 기존 `translations/view` 검사를 `translations/write`로 바로잡는다. 오너 전용 UI・직접 진입・서버 쓰기 권한을 각각 검증한다. |

### 동적 대화상자・공통 UI

- `otp-verify-overlay`: TOTP/백업코드 입력・취소・서버 검증・원래 메뉴 재진입 유지. 도감/댓글/카드뉴스 로더는 패널 진입 성공 뒤 `gw:admin-panel-shown` 이벤트로 실행한다. 계정은 접근이 허용되어 실제 `active`가 된 패널을 관찰하는 기존 방식을 유지한다. 접근 거절・미저장 이동 취소・OTP 취소 때 숨긴 패널을 불러오지 않으며 댓글 패널은 OTP 재진입 때 목록과 대기 수를 다시 조회한다.
- OTP 등록 QR/확인・일회 백업코드・해제 prompt, 세션 5분 전 경고와 만료/재로그인 overlay: 내 계정/인증 업무에 유지. 보안 상태와 단순 화면 이동을 구별한다.
- `v3-ti-modal-overlay`・`v3-ti-articles-modal`: 태그 집계/기사 목록・페이지 이동・미리보기/공개 링크 유지. 차트 표시 설정 popover는 글자/간격의 로컬 선호값으로 유지하며 서버 설정과 혼동하지 않는다.
- 네이티브 confirm/prompt: 기사/자료/카드뉴스/계정/프리셋 삭제・도감/행사 일괄 적용・아이디/비밀번호 재설정・발행 차단・기본값 복원・댓글 거부 사유에 쓰인다. 이번 재편에서는 보존하고 실제 데이터로 실행 검증하지 않는다.
- 검색・필터・정렬・페이지 이동・기간 선택・빈 상태・로딩/오류・저장 중 비활성화・토스트・모바일 관리 메뉴・키보드/현재 항목 표시는 각 업무의 공통 확인 대상이다. 본문의 Editor.js, 개인정보 방침의 편집기, 카드뉴스 iframe은 기존 도구로 유지한다. 작성 변경 감지는 Editor.js의 의미 있는 `onChange`를 사용하고 빈 편집기 재설정은 `render({blocks:[]})`로 처리하여 프로그램 초기화만으로 미저장 상태가 되지 않도록 한다. 실제 편집기 입력/빈 재설정・작성/복원/이동은 로컬 합성 환경에서 검증했고 운영 자료의 저장 검수와 구별한다.

### 작성・자동저장・발행의 추가 수정

- 자동저장 요청을 보낸 뒤 입력이 바뀌면 이전 응답으로 새 입력/이미지와 미저장 표시를 덮지 않는다. 저장 당시 변경 순번과 현재 순번을 비교하고 다음 저장을 이어서 예약한다.
- 임시저장 중 발행과 발행 중 중복 저장을 막고, 저장/발행이 진행되는 동안 다른 패널로 이동하지 않는다. 발행 중 예약된 자동저장은 짧게 재시도하며 이전 초안 저장과 겹치지 않는다.
- 발행 성공 뒤 이전 초안 ID를 비우고 후속 입력은 발행된 기사 ID에 연결한 새 초안으로 보존한다. 발행 중 추가 입력은 발행 응답 뒤에도 미저장 상태로 남기고, 실패하면 필요한 자동저장을 다시 예약한다.
- 100ms 재시도와 일반 자동저장 타이머는 같은 취소 경로를 사용한다. 사용자가 변경을 버리고 이동했을 때 나중에 이전 화면의 초안을 저장하지 않는다.

이 조건은 실제 production 함수의 합성 실행과 지연된 API 응답을 사용한 로컬 브라우저 시험으로 확인한다. 실제 운영 DB의 콘텐츠 CRUD・계정 변경・유료 AI 실행은 하지 않았다.

### 제거・검토 결론

제거한 UI는 효과 없는 추천 수동 검색/선택/해제/정렬, 중복 `account-security` 폼/OTP, 숨긴 설정 보조 메뉴, 상단의 중복 KMS 링크다. 기존 런타임 바인딩과 겹친 인라인 refresh/filter/save/modal 이벤트 폴백도 정리 대상에 포함하며 동일 행위가 두 번 실행되지 않는지 합성 검증한다. 데이터・서버 기능은 삭제하지 않는다. 공개 메뉴명을 복원하고 `편집자·접근 관리`는 `저자명 관리`로 바로잡았다. 대량 치환/CSV/복제/비용 표시/차트 표시 옵션/권한 프리셋 등은 목적이 구별되며 사용 여부를 확인하지 못했으므로 유지 후 검토한다. 메뉴 감소 자체를 기능 재검토 완료의 근거로 삼지 않는다.
